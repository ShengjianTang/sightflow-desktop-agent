# 运行配置说明

项目由 Electron 主进程、preload、React 主界面及框选窗口组成，没有需要另行启动的业务后端或数据库。先完成依赖安装即可打开界面，AI 参数只在启用相应功能时校验。项目不自动读取 `.env` 文件；火山方舟和硅基流动密钥均可在应用内手动填写，硅基流动也支持启动环境变量作为后备。不要写入源代码、Provider bundle 或提交到 Git。

## 配置入口和用途

| 配置项                                | 填写位置                                                              | 用途 / 缺失时行为                                                                                                                      |
| ------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| 火山方舟 API Key                      | 设置 → 基础配置 → 视觉接口密钥；内置豆包配置中的 API Key 也保存到此处 | VLM 布局识别、内置豆包截图回复、从轨迹学习。缺失或仅空格时返回明确提示；自定义 Provider + 手动框选不需要它。                           |
| 火山方舟模型 / 推理接入点 ID          | 设置 → 基础配置 → 视觉模型 / 推理接入点 ID                            | 测试连接、视觉识别和内置豆包聊天共用。需要选用当前 API Key 有权访问且支持图片输入的 ID。                                               |
| 硅基流动 API Key                      | 设置 → 智能体 → 硅基流动多模态 → API Key                              | 保存于本机 `settings.json` 的 `siliconFlow.apiKey`；留空时使用启动环境变量 `SILICONFLOW_API_KEY`。聊天截图、布局和本地图片识别共用。   |
| 硅基流动视觉模型                      | 设置 → 智能体 → 硅基流动多模态 → 视觉模型                             | 保存于 `siliconFlow.model`；留空时使用 `SILICONFLOW_VISION_MODEL`，再回退到 `Qwen/Qwen3-VL-30B-A3B-Instruct`。                         |
| 聊天接口地址、API Key、模型及其他参数 | 设置 → 智能体 → 选中 Provider → 配置表单                              | 表单由该 Provider 的 manifest 声明；不同服务要求不同，不能把聊天接口地址误填为 manifest 地址。必填项缺失会阻止引擎启动，界面保持可用。 |
| Provider manifest 地址                | 设置 → 智能体 → 聊天服务配置清单地址 → 安装                           | 安装可信 Provider 的代码与配置声明。支持 HTTPS 和本地 file:/// 路径；下载失败不会覆盖当前配置。安装成功后填写表单。                    |
| 目标应用和截图/输入区域               | 主窗口 → 目标应用 → 开始框选（需要时）                                | 微信、企业微信默认使用 VLM；其他应用使用手动框选。首次启动缺少区域会打开向导，取消会返回失败提示。                                     |
| Provider Hub 地址（可选）             | 启动进程的环境变量 `SIGHTFLOW_PROVIDER_HUB_URL`                       | 默认 `https://sightflow.dev/provider-hub.json`，用于获取 Provider 目录，不是聊天接口。只填写不含凭证的地址。                           |
| 本地 Skill 服务端口（可选）           | 启动进程的环境变量 `SIGHTFLOW_SKILL_PORT`                             | 默认 12680；有效范围 1024–65535。非法值回退默认端口。端口冲突只尝试一次备用端口，然后放弃服务，不影响桌面窗口。                        |

切换 Provider 或更换其 manifest 地址会清除上一 Provider 的通用聊天配置，防止旧密钥被传给另一服务。火山方舟视觉配置和硅基流动配置分别保存在独立设置项中，切换智能体不会清除它们。同一个 Provider 的配置修改保留其他字段；清空视觉密钥后不再回填旧密钥。布尔类型配置使用复选框，`false` 是有效值。运行中保存配置会停止当前引擎，下一次启动加载新配置，防止旧 Provider 或旧密钥继续用于后续请求。

## 硅基流动图片能力

首选在 **设置 → 智能体 → 硅基流动多模态** 填写 API Key 和平台提供的视觉模型 ID，点击 **保存配置** 或 **启用此智能体**。主窗口的图片识别即使当前选用豆包，也会使用已保存的硅基流动配置。若不想保存密钥，可将 API Key 留空，在启动应用的同一个 Windows PowerShell 终端中设置环境变量（下面的密钥值只是占位说明）：

```powershell
$env:SILICONFLOW_API_KEY = '<你自己的硅基流动 API Key>'
$env:SILICONFLOW_VISION_MODEL = 'Qwen/Qwen3-VL-30B-A3B-Instruct' # 可省略
npm run dev
```

应用内已保存的值优先于环境变量；保存时清空 API Key 才会回退到环境变量。修改环境变量后需完全退出并重新启动应用。设置页的状态 IPC 只返回是否已配置和生效模型，不返回密钥；但应用内保存的密钥会经本机设置 IPC 到达渲染界面，当前 electron-store 的 `settings.json` **没有加密**，请保护本机用户数据目录。原有火山方舟设置不受影响。启用硅基流动后，微信/企微默认 VLM 布局识别和聊天截图回复改用该服务，不要求另填火山方舟视觉密钥。自动回复只能依据截图中可见的图片缩略图，不能读取聊天里未打开的原图；模糊或看不清时不应猜测。

硅基流动的 `/v1/chat/completions` 与火山方舟的 `/api/v3/responses` 是不同服务。**不能仅把豆包模型 ID 或火山方舟 API Key 填入硅基流动表单**；要用豆包请选内置 **豆包 Seed**，使用方舟控制台已开通且支持图片输入的 `doubao-seed-evolving` 或对应 `ep-` ID。硅基流动视觉模型建议从 `Qwen/Qwen3-VL-30B-A3B-Instruct` 开始，实际以硅基流动控制台对当前账号开放的模型 ID 为准。

主窗口 **图片处理 → 选择图片** 支持本地 PNG/JPEG（最大文件 12 MB，处理后的请求图片最大 8 MB），可填写提示词并点击 **识别图片**，对选中的完整图片发起硅基流动多模态请求。该操作不要求切换聊天 Provider，但需要已保存的硅基流动密钥或 `SILICONFLOW_API_KEY`。**发送到当前会话** 与识别是独立操作：仅 Windows 微信/企业微信、暂停引擎后可用；确认当前会话后经剪贴板粘贴发送，模型不能自动触发图片发送。发送前会核对目标窗口焦点，但仍须在聊天窗口确认最终发送对象及结果。图片预览会暂时传到渲染界面，主进程中的令牌与图片在成功发送后失效；不要在不可信的桌面环境操作敏感图片。Unicode emoji 可作为普通文字发送，微信贴纸/自定义表情暂不支持。

常见错误：应用内与环境变量都没有硅基流动密钥时会提示填写；`HTTP 401/403` 检查密钥和模型权限；`HTTP 404` 检查模型 ID 与账号可用性；`HTTP 400/413` 检查图片格式和大小；`HTTP 429` 检查频率或额度；90 秒超时需检查网络和服务状态。上游错误正文不会显示。图片发送若提示焦点变化、未找到目标窗口或“可能已粘贴但未发送”，请先检查目标会话和输入框，避免重复发送。请不要将硅基流动密钥粘贴到火山方舟设置中。

## 公开默认地址与模型

内置火山方舟服务地址为 `https://ark.cn-beijing.volces.com/api/v3`（界面只读），实际请求路径为 `/responses`。默认模型为 `doubao-seed-evolving`，与控制台「快速接入测试」中已开通的模型 ID 和 Responses 示例一致。请在 **设置 → 基础配置 → 视觉模型 / 推理接入点 ID** 核对该值；若控制台显示其他已开通且支持图片输入的模型或 `ep-` 接入点 ID，可在此手动修改。测试连接、VLM 识别和内置豆包聊天都使用此值。测试连接是文本请求；启动引擎后的布局识别才会实际测试图片输入。自定义聊天 Provider 的模型由其表单单独配置。

相关源码位置：

- [src/core/ai-config.ts](../src/core/ai-config.ts)：视觉服务默认地址、模型、文本 30 秒和图片 90 秒超时；主进程、视觉客户端和界面共用。
- [resources/providers/volcengine-ark/manifest.json](../resources/providers/volcengine-ark/manifest.json)：内置聊天 Provider 的配置字段和默认模型。
- [resources/providers/volcengine-ark/provider.bundle.js](../resources/providers/volcengine-ark/provider.bundle.js)：独立分发的内置聊天 Provider，包含相同的公开默认地址及模型；密钥只从运行时配置读取。
- [src/main/index.ts](../src/main/index.ts)：Provider Hub 默认地址及环境变量读取、设置 IPC 和引擎启动校验。
- [src/main/settings.ts](../src/main/settings.ts)：设置归一化、旧配置兼容与 Provider 配置隔离。
- [src/main/skill-server.ts](../src/main/skill-server.ts)：本地控制服务端口与失败处理。

旧版自动保存的 `doubao-seed-2-0-lite-260215` 会迁移为新默认值，不覆盖其他手动填写的模型/接入点 ID。密钥由用户在 **设置 → 基础配置 → 视觉接口密钥** 手动输入，保存到本机 electron-store 的 `settings.json` 中 `vision.apiKey`；模型保存在 `vision.model`。无需修改源码或 Provider bundle。内置豆包也可在 **设置 → 智能体 → 豆包 Seed** 填写并保存相同的密钥和模型。

## 认证及模型错误

- `HTTP 401`：检查 API Key 是否有效、是否复制完整。
- `HTTP 403`：检查所填模型或推理接入点的开通状态、访问权限。
- `HTTP 404`：检查模型/接入点 ID 是否存在、是否已开通或有权限，并确认服务地址；404 不能单独证明密钥错误。
- 超时、连接失败、无回复文本、其他 HTTP 错误仍分别显示，不会把可能包含敏感信息的上游响应正文输出到界面或日志。

## 外部服务不可用时

- 文本连接测试最长等待 30 秒；视觉截图与内置豆包图片回复最长等待 90 秒，均覆盖响应头和正文，并关闭深度思考以降低回复延迟。连接失败、HTTP 错误或无效返回值会转换为可展示的失败结果/事件，不作为成功回复发送。连续超时请检查代理/网络、模型图片调用权限与服务状态。
- 微信/企微启动时只调用必需的主布局识别；可选的未读红点位置在首次轮询时按需识别。主布局遇到网络错误或超时会在 5 秒后自动重试一次，第二次仍失败才停止引擎；无效布局等非暂时性错误不会重试。未读识别失败后冷却 60 秒，避免持续发送耗时图片请求，之后自动再试；停止引擎会清除冷却状态。
- 智能体页远端目录加载失败会显示内联提示；内置豆包无需该目录即可使用。保存配置会停止当前引擎，请在设置后返回主窗口重新启动。
- 聊天 Provider 报错会记录错误并等待下一轮重试；视觉布局识别失败会停止引擎并同步界面状态，桌面应用保持可用。
- Hub 及目录内 manifest 的每次请求最多 10 秒；部分 Provider 清单不可用时保留成功加载的条目。整体更新失败保留已有缓存、内置 Provider 和当前已安装 Provider。
- 安装时 manifest/bundle 的每次远程下载最多 15 秒。已安装 Provider 保存配置时不必重新下载，离线仍可修改。
- 第三方 Provider 需要自行给内部网络请求添加超时并返回 `error` 事件；宿主会捕获其抛出的异常，但无法保证任意第三方代码的行为。只安装可信 Provider。

## 本地 Skill 控制服务

只监听本机回环地址 `127.0.0.1`，默认 `http://127.0.0.1:12680`，提供：

- `GET /skill/status`
- `POST /skill/start`
- `POST /skill/pause`

主端口占用时尝试“主端口 + 1”；主端口为 65535 时备用为 12680。实际端口会打印在启动日志中，调用方需使用该端口。服务没有单独的远程认证参数，应只供本机可信工具使用。

Windows PowerShell 的可选配置示例（仅当前终端生效）：

```powershell
$env:SIGHTFLOW_PROVIDER_HUB_URL = 'https://your-provider-host.example/provider-hub.json'
$env:SIGHTFLOW_SKILL_PORT = '12680'
npm run dev
```

使用默认 Hub 时不要设置第一个环境变量。火山方舟和硅基流动的 API Key 分别填写在各自应用表单中；硅基流动环境变量为可选后备。

## 安装、启动与检查

使用 Node.js 22 LTS 和 npm；Windows 的原生依赖构建需要 Python 以及 Visual Studio“使用 C++ 的桌面开发”工作负载。macOS 需要系统授予“辅助功能”和“屏幕录制”权限。

```powershell
npm ci
npm test
npm run typecheck
npm run lint
npm run build
npm run dev
```

`npm test` 只使用测试占位值、模拟 Provider 和本机回环 HTTP 服务，不连接真实 AI、不截图、不移动鼠标、不发送聊天消息。

`npm run build` 只验证并构建 JS/HTML 资源，不能替代 Electron 和原生模块的运行检查。若曾用 `--ignore-scripts` 安装依赖，Electron 下载及原生模块编译均被跳过：

- Electron 二进制不存在时，启动报 `Electron uninstall`；网络恢复后可运行 `node node_modules/electron/install.js` 重试下载项目锁定版本。
- 安装好 C++/Python 工具链后，使用 `npm ci` 重新完成正常安装及项目的 postinstall 重建。
- 缺少 `node-window-manager` 时 VLM 窗口查找会失败；手动框选不依赖该模块，但实际鼠标键盘发送仍依赖 `@hurdlegroup/robotjs`。缺少机器人模块时不能完整执行回复。

开发脚本中的 `TEST_MODE` 和 `ELECTRON_RENDERER_URL` 由测试命令/electron-vite 使用，普通运行无需手工填写。项目未配置发布上传或代码签名凭证。

## 回复定位与未读检测

如果能识别消息却点错输入框，先退出旧版 SightFlow，再从当前源码运行 `npm run dev`。`npm run build` 已生成当前源码的 `out/` 资源；此前安装的 EXE 不会随源码自动更新。

当前自动识别流程统一以 Electron 逻辑像素（DIP）记录窗口和布局，在真正移动鼠标时才转换为 Windows 物理屏幕像素，以支持缩放和副屏。普通窗口移动会更新坐标；窗口尺寸、所在显示器或 DPI 改变时会清除旧布局并重新测量。首次识别及重新测量仍需要调用已选视觉模型，所以等待时间受网络和模型响应影响。

- 自动识别优先定位底部实际可编辑的文字输入区域。聊天记录框轻微包含输入框时，自动裁去重叠部分；编辑框过小或不合理时单独复核一次。模型仅返回前三个布局区域时，保留从聊天区推导输入框的兼容方式；无效区域不会直接用于点击。
- 当前对话先做聊天区像素比较；其他联系人从可见头像角标列扫描小型红色圆点或数字气泡，发现后点击对应行，并检查聊天区是否变化。置顶联系人不会被一律当成目标联系人。联系人列表检测不再要求导航栏聊天按钮可见；右侧只有空白微信占位图时，也会扫描左侧列表、打开未读行，然后重新测量聊天输入框。
- **可见列表有数字角标但不切换**：未读扫描现在以搜索框下方的完整可见联系人列表为范围，而不从“第一个头像”的位置向下扫描窄条。头像被识别成整行、内部小图案、裁切的首行或位于未读联系人下方时，不再直接判定无未读。列表发现红色候选但头像位置不可靠时，会使用当前视觉模型复核对应行，校验红点与头像的相对位置后更新头像列；通常后续轮询仅做本地像素检测。复核失败或未确认时至少间隔 5 秒再试，不每轮调用模型。整个列表截图没有红色候选时，不额外发起复核请求。
- 复核期间列表滚动、重排或窗口移动会取消旧坐标点击。连续两次定位失败或点击后聊天区未变化，会清除旧未读位置并重新检测。日志区会区分“列表没有红色未读角标”“正在复核未读联系人”“列表发生变化”等状态，而不是只显示泛化的等待信息。
- 正常空闲轮询间隔为 1.2 秒，截图、扫描、窗口切换和模型分析耗时另计。定位失败的退避为 5 秒；截图或检测错误会明确显示，不再直接当成“无未读”。
- 截图在一轮检测中短暂复用，每轮聊天比较、点击/发送后和设置聊天基线前都会刷新，避免用旧画面判断新消息。
- 手动发送图片仍需要先暂停引擎。缓存已清空时，会使用当前 Provider 或已保存的框选区域重新测量输入框，不会启动自动回复。

自动识别模式下，回复模型接收完整应用窗口，以保留群聊头像、消息左右方向、会话名称和输入框信息。手动框选仍按聊天记录区截图。火山方舟及硅基流动的内置回复规则默认处理普通私聊和群聊消息，包括“有人没”“在吗”等短问句，不要求被 @；图片、截图和表情仍可生成文字回应。明确属于自己的消息、系统通知、非聊天页面或已有未发送草稿时会跳过。

内置 Provider 输出按时间排序的 `messages` 列表（发送方、文字或图片/表情描述、头像位置），并给出最后一条消息及本次回复。程序核对整个列表的顺序、头像左右方向及最后一条消息是否一致，只将实际回复文字交给输入设备。模型遗漏消息列表、顺序矛盾或发送方证据不充分时复核一次；仍不明确则不发送。

自动回复按“最后一次自身回复之后，对方连续发送的一批消息”处理。截图前会等待约 800 毫秒观察画面是否稳定；持续变化时最多进行 2.4 秒的间隔采样，再进入模型分析（不含截图或网络耗时）。每次请求携带本轮引擎运行期间按会话保存的上下文和未回复批次，让模型结合多条文字、图片、表情与指代关系生成一次连贯回复。每个会话最多保留 48 条上下文消息和 48 条待回复消息，每条最多 2,000 字符；最多保留 50 个会话，停止引擎后清空。

防重复判断同时检查已回复的对方消息批次、最近已发送文本及已处理截图。仅画面变化或模型给出一个左侧头像，不能让自己的旧回复变成新消息。相同文字确实出现在最新自身回复之后，可以正常处理；缺少这个边界时会保守等待。微信默认绿色右侧气泡还有本地像素辅助检查，用于拦截模型漏看下方自身消息、错误选中上方旧头像的情况；其他主题仍依赖结构化识别。自定义 Provider 的普通文本输出仍可用于首次回复，后续需提供 `messages` 和完整发送方证据，详见 Provider 接入文档。

聊天基线保存本次模型实际分析的截图，避免将模型分析期间的新消息误标为已处理。自动识别模式发送前核对会话标题和聊天内容，手动框选模式也核对聊天内容；变化时取消旧回复，保留此前识别的待回复内容并重新合并分析。如果用户随后手动回复，确认最后为自身消息后会结束旧的待回复批次。每次观察只处理一次最终结果，排队期间的重复观察和停止引擎前的旧结果不会再次发送。

上下文来自已识别的截图，不读取微信数据库。超出可见范围且从未被引擎识别的消息无法自动补齐，也不会自动滚动拉取历史。模型仍可能发生 OCR、图片含义或指代误判；测试验证的是消息传递、边界检查和发送控制，不能保证真实模型的每次回答都正确。手动框选模式没有会话标题身份识别，适用于固定的单个会话；手动换联系人时应停止引擎后重新启动，避免沿用上一会话上下文。

启动时暂未确认输入框，或当前是公众号/网页等没有聊天输入框的页面，会保持引擎运行并每 5 秒检查恢复。同一画面短时间内不会重复调用布局模型，返回普通聊天后重新测量。浏览器抢走焦点时等待用户返回微信，不强行抢回焦点；识别期间聊天对象或页面改变会取消旧回复。发送中断后会显示实际错误原因；已粘贴或已按 Enter 的回复不会作为原发送事件自动重试，需检查输入框中的内容。

请让微信/企业微信完整位于一块显示器内，取消最小化并避免遮挡。红点识别是屏幕视觉检测，滚动范围外的联系人、灰色免打扰标记、特殊主题或类似红点的头像图案仍可能漏检或误判。手动框选模式只观察当前打开的对话，不会自动切换其他联系人；移动窗口或改变显示缩放后需重新框选。

可能出现的提示：

- `输入框暂未可靠识别`：已进行输入框复核，引擎等待后自动重试；持续出现时可使用手动框选。
- `当前页面没有聊天输入框`：当前页面不适合自动发送，返回普通聊天后自动恢复。
- `输入框坐标不可用或超出目标窗口`：旧布局已失效或区域不合理，重新启动引擎测量布局。
- `无法获取联系人头像或聊天入口区域`：可见未读布局识别失败，短暂等待后重试；检查窗口可见性及视觉模型配置。
- `尚未打开聊天`：已识别空白聊天占位页，会尝试打开左侧可见未读联系人；无未读时继续等待。
- `已拦截自我回复`、`同一聊天画面已处理`：已识别自身发送内容或重复画面，没有再次发送。
- `这批对方消息已经回复`：画面变化但未找到新的待回复批次，避免重复发送。
- `消息顺序或头像位置矛盾`、`最新消息与消息列表不一致`：消息证据未通过核对，需要重新识别。
- `已合并本会话 N 条待回复消息`：将连续消息作为一个批次生成一次回复。
- `尚未确认新的左侧消息`、`最新消息头像不在聊天记录区内`：发送方证据不足或定位不可靠，等待新画面重新确认。
- `模型分析期间聊天内容已改变`：为避免答错问题已取消旧回复，引擎会重新识别最新内容。
- `目标聊天窗口失去焦点`：已取消当前发送，引擎继续等待恢复；如果已粘贴内容，先检查输入框。
- `识别期间聊天对象或页面已改变`：旧回复已取消，将重新识别当前会话。
- `目标窗口跨屏或大部分位于屏幕外`：将目标窗口完整移入一块显示器内。

## 配置与敏感数据的保存

设置保存到 `app.getPath('userData')/settings.json`，已安装 Provider 保存到同目录的 `providers/`，轨迹与经验卡片位于 `worktrace/`。用户数据目录由 Electron 决定，开发环境与安装版可能不同。

当前设置使用 electron-store 的本地 JSON 持久化，**没有配置密钥加密**。API Key 不写入仓库，但仍需保护本机用户数据目录，不要分享 settings.json、截图、聊天轨迹或含业务数据的日志。HTTP 错误只展示状态码，不把服务端可能回显密钥的错误正文写入日志。
